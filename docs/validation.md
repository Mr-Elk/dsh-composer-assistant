### 关于恢复脚本的更正

开发过程中曾把"恢复脚本在 `originallyMissing` 链接处失败"记为 `0.1.1` 的阻断性缺陷。复核确认该现象由**开发会话沙箱对工作区盘符的文件系统重定向**引起（junction 被写成 `\??\Global\…`，同一进程无法跟随），不属于归档或脚本缺陷：在普通用户路径（C 盘临时目录、随包 Node 24.19.0）上，`0.1.1` 原始归档的完整流程可正常完成，105 条测试全部通过。`0.1.2` 对恢复脚本的改动因此是**健壮性改进**（幂等、`--repair`、缺目标跳过、链接识别、创建兜底），不是对既有缺陷的修复。

## 2026-11-03：Issue #3 / PR #4 每小时额度审查

审查对象：[PR #4](https://github.com/Mr-Elk/dsh-composer-assistant/pull/4)，原提交 `5bcd79e`。以上 0.1.x 记录不代表本次验证。

原补丁在真实 `AssistantHostRuntime`、`DomainFacility` 和官方 JSON 后端上复现了三项失败：首次读取未结束时另一请求进入模型准备；已有记录尚未写完就进入模型准备；不限次数时保存 2049 条记录后重开触发 `invalid-record`。原来的核心、设置存储、Gateway 共 54 项测试通过，不能排除这些问题。

最终实现使用一个预算队列串行处理读取、判断和写入，复用共享的域初始化 Promise；打开失败会清除失败的 Promise，后续请求可重试。模型调用必须等待存储确认；写失败不调用模型，也不更新计数。取消、超时或停用发生在写入期间时，迟到的写入不能继续启动模型；已保存的预留仍计入额度。

官方 `@deepseek-ai/dsh-storage-json@0.2.1-rc.2` 的逐条存储会把不可读、损坏或未知版本记录当成不存在。因此预算单独使用 `input_assistant_budget` 单文件域，读错误、格式错误和版本不匹配会报告失败，不会清空历史。原 `input_assistant` 设置和草稿域的版本 1、格式和表声明保持原样。测试也确认原 PR 添加表且不升版本本身可兼容；采用独立域是为了严格处理读取失败。

实际执行环境：macOS、Node 22.23.2、锁定的 DSH 存储包 `0.2.1-rc.2`、Typert/Gateway 发布包。新增测试使用真实插件、Gateway、Session、Domain 和磁盘文件。延迟控制包住真实操作；故障通过文件与目录冲突或损坏本次测试生成的文件触发。没有伪造存储服务，也没有配置付费模型；被放行的请求进入真实 LLM 运行时后因未配置提供商而结束。
