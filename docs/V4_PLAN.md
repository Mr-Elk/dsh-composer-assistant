# 输入助手 v4 开发计划

日期：2026-11-02
状态：设计已定稿，代码未开始
目标：把 v4 设计落到插件里，完成真实宿主验收并发布

## 0. 结论

- 设计已经收尾，不再改结构；剩下的是实现、验收和发布。
- 一个人做，约 **23–25 个工作日**，按 4–5 周排；两个人可以压到 3 周左右。
- 关键路径：**基础改造 → 设置页 / 齿轮弹窗 → 情境操作 → 状态补齐 → 真实宿主验收 → 发布**。
- 最大技术风险不是界面，是两件事：
  1. 设置页要拿到 DSH 的模型列表（根级页面没有会话目录）。
  2. 语言要跟随 DSH 时，需要拿到 DSH 当前 locale。
- 这两件各安排一个 0.5 天 spike，先验证再展开。

## 2. 目标与非目标

### 目标

- 输入框：星形 16px + 齿轮；去掉 `⌄`。
- 齿轮弹窗：三项设置 + 保存 / 取消；标题旁 i；不出现操作。
- 操作：选中保护、优化后查看/撤销、候选卡建议操作；`Esc` 忽略建议。
- 设置页：语言、三个功能开关、建议长度、优化强度、辅助模型、高级收起、恢复默认 + 保存、关于链接。
- 语言：跟随 DSH / 中文 / English。
- 辅助模型：从 DSH 模型列表选，不手填 provider/model。
- 首次提示：第一次打开输入框出现一次，本地记住。
- 真实宿主验收、打包、发布。

### 非目标

- 不做自动更新。
- 不做模型 ID 手动输入。
- 不把操作塞回设置。
- 不新增设置项，除非通过“可解释、安全、有默认、可验证”四条。
- 不重写提示词策略；本轮主要是界面、交互和配置。

## 4. 阶段明细

### 阶段 1：基础改造（3 天）

**目标**：把配置、语言、模型列表、设置草稿四块地基打好，界面先不动。

任务：

1. **配置模型**
   - 删除 `nextTrigger`（手动模式取消，永远自动预测）。
   - 新增 `language: 'follow' | 'zh' | 'en'`，默认 `follow`。
   - 保留 `provider` / `model` 成对存储；界面只暴露模型。
   - 旧记录迁移：未知键忽略；`nextTrigger` 读到时忽略；下一次保存写干净。
   - 更新 `src/core/types.ts`、`config.ts`、`src/index.ts` schema、`SETTINGS.md`。

2. **i18n**
   - 新增 `src/core/i18n.ts`：`zh` / `en` 字典，key 覆盖设置页、弹窗、首次提示、气泡、关于。
   - `follow` 解析为 DSH 当前 locale；拿不到时回落 `zh`。
   - 宿主错误消息按错误码映射；未知错误保留原文。
   - 浏览器组件用统一 `t()`；不在组件里散落中文字符串。
   - 测试：key 完整、无缺失、`follow` 回落。

3. **模型列表**
   - Spike（0.5 天）：确认 DSH 模型目录能否在根级设置页读取。
   - 优先复用共享 catalog；否则加只读 `models/list` 宿主接口，返回 provider 分组和模型显示名。
   - 浏览器缓存列表；加载中/失败状态。
   - 失败时只保留「跟随输入框」；不阻塞设置页。
   - 测试：成功、空列表、失败、模型被移除。

4. **设置草稿**
   - 一个 `SettingsDraft`：`accepted` / `draft` / `dirty` / `save` / `cancel`。
   - 保存时校验全部字段，和 accepted 做 diff，只提交变化字段。
   - 弹窗和设置页共用这套模型；隐藏字段不被清空。
   - 页面与弹窗同时打开时：页面重新获得焦点刷新；如果页面有未保存改动，提示冲突，不静默覆盖。

**文件**：`src/core/types.ts`、`config.ts`、`i18n.ts`、`src/index.ts`、`src/browser/runtime.ts`、`src/host/rpc.ts`、`runtime.ts`、`storage.ts`、`tests/core.test.ts`、新增 i18n/model 测试。

**验收**：typecheck、单测通过；配置迁移有测试；模型列表失败能回落；无 UI 回归。

**风险**：模型列表接口可能受 DSH 版本限制；locale API 可能不可用。两项都有回落方案，不阻塞。

### 阶段 2：设置页（4 天）

**目标**：实现 v4 设置页。

任务：

1. 布局：通用 / 功能 / 建议 / 优化 / 辅助模型 / 高级（默认收起）/ 恢复默认 + 保存 / 关于链接。
2. 删除触发方式；建议组只剩建议长度。
3. 圆圈 i 提示：悬浮、键盘聚焦、触屏点按；空间不足自动翻转。
4. 高级收起：默认收起，展开只记当前界面，不写设置；展开后显示 5 项。
5. 条件置灰：
   - 提示词优化关闭 → 优化强度置灰。
   - 回复后预测和输入续写都关闭 → 建议长度置灰。
6. 语言：跟随 DSH / 中文 / English；保存后整页切换；跟随 DSH 时随 DSH locale 变化。
7. 辅助模型：DSH 列表下拉；默认跟随；i 显示当前模型、列表来源、计费；失败/移除回落提示。
8. 关于：表单外链接，打开独立弹窗；版本、插件页更新说明、复制命令；Esc 关闭、焦点回入口；不参与保存。
9. 保存状态：加载、断线、保存中、成功、失败、未保存、放弃。
10. 无障碍：label、aria、focus-visible、键盘可达。

**文件**：`src/browser/settings.tsx`、`styles.ts`、`runtime.ts`、`components.tsx`（InfoTip 可复用）、i18n 字典、`tests/browser-settings.test.tsx`。

**验收**：浅/深色截图；窄窗 720 / 200% 不横向滚动；键盘可开 i 提示和高级；保存全部字段；条件置灰正确。

### 阶段 3：输入框与齿轮弹窗（3 天）

**目标**：替换旧 `⌄` 菜单。

任务：

1. 工具栏：星形 16px；齿轮 15px；2px 间距 + 细分隔线；去掉 chevron。
2. 齿轮弹窗：三项设置（回复后预测、输入续写、建议长度）+ 取消/保存。
3. 标题旁 i：完整设置路径提示。
4. 保存：写整份草稿 diff；保存后关闭；无改动置灰；取消/点外面丢弃。
5. 弹窗与设置页冲突处理；保存后广播设置。
6. 删除旧动作菜单（保留 controller 动作方法给情境 UI 用）。

**文件**：`components.tsx`、`styles.ts`、`controller.ts`、`runtime.ts`、`tests/browser-ui.test.tsx`、`browser-controller.test.ts`。

**验收**：弹窗只有三项；保存/取消/关闭；键盘；深浅色；无旧动作列表。

### 阶段 4：情境操作（4 天）

**目标**：操作跟着情境走。

任务：

1. **选中保护**：有选区时在文字上方浮出「保护」；点击锁定；不抢选区；键盘可达。
2. **优化结果条**：优化完成后输入框顶部出现「已优化 / 查看改动 / 撤销 / 复制原文」；没有改动时不出现；编辑后按现有逻辑失效。
3. **候选卡**：保留换一条/采纳/×；灰字建议加 `Esc` 忽略（补 controller 键处理）。
4. 删除「暂停至下次编辑」入口；`×` 和 Esc 覆盖。
5. 删除手动预测逻辑（已删 `nextTrigger`）；`换一条` 仍可用。
6. 浮层定位：选区 chip、结果条、候选卡在窄窗和滚动时不越界。

**文件**：`components.tsx`、`styles.ts`、`controller.ts`、`dom.ts`、`tests/browser-ui.test.tsx`、`browser-controller.test.ts`、Chrome 冒烟脚本。

**验收**：真实浏览器选中→保护；优化→查看/撤销；候选卡；Esc；无菜单操作。

### 阶段 5：首次提示（1 天）

**目标**：第一次打开输入框出现一次说明。

任务：

1. localStorage key（带版本），每个浏览器只显示一次。
2. 位置：输入框上方，箭头指向优化+齿轮；不挡输入；可 Esc/点外面/知道了关闭。
3. 文案走 i18n；深色/窄窗适配。
4. 测试：第一次出现、第二次不出现、关闭后不重复。

**文件**：`components.tsx`、`styles.ts`、`i18n.ts`、`tests/browser-ui.test.tsx`。

### 阶段 6：状态与适配（2 天）

**目标**：把状态补齐，不靠真实使用才发现。

任务：

1. hover / focus-visible / disabled / loading / error 全检查。
2. 深色条件状态：弹窗、i 提示、结果条、选中 chip、关于弹窗。
3. 窄窗 720 / 200% 缩放；工具条不挤压。
4. 键盘：Tab 顺序、Esc 关闭、i 提示可达。
5. 截图归档到 `docs/design/`，浅/深各一套。

### 阶段 7：测试与验收（4 天）

**目标**：证明不是“看起来能用”。

任务：

1. 单测：配置迁移、i18n、模型列表、设置草稿、条件置灰、保存 diff。
2. 浏览器夹具：设置页、弹窗、选中 chip、结果条、候选卡、首次提示。
3. Chrome 冒烟：真实 Lexical + 生产组件；0 次付费调用。
4. Windows Edge：主题/灰字/候选卡；CI 跑。
5. 宿主：Gateway、包加载、RPC、存储迁移。
6. 真实 DSH rc.5 隔离实例：设置保存/重启、语言切换、辅助模型列表、Tab/撤销、菜单、失败保留、`/` `@`、IME 真机。
7. 打包：`pnpm pack`、`test:package`、`publish:check`；修掉旧 `lib/` 误报。
8. 截图与对比图更新。

**验收门槛**：全部单测/浏览器冒烟通过；rc.5 人工清单通过；Edge CI 绿；包校验通过。

### 阶段 8：发布（2 天）

**目标**：0.3.0 发布并从 npm 安装。

任务：

1. 版本策略：建议 **0.3.0**（0.2.0 本地包已存在，v4 改动大）；同步 `package.json`、`src/core/version.ts`、CHANGELOG。
2. 发布门禁：修 `verify-publish.mjs` 的“旧 lib 也能过”问题（源码哈希/build stamp）；清 `dist/` 旧包。
3. 仓库：建 GitHub origin，推 main，打 `v0.3.0`，配 NPM_TOKEN；Windows CI。
4. npm：登录、发布验证过的 tarball、检查 npm 页面和文件清单。
5. 安装：desktop profile 改为 npm 版本，重启验证；回滚方式写进 README。
6. 商店素材：README 截图、screenshots.json、版本说明。
7. 发布后：rc.5 冒烟、收集反馈、记录已知限制。

## 6. 风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| DSH 根级拿不到模型列表 | 辅助模型下拉做不了 | 先 spike；加只读 `models/list`；失败只保留跟随 |

| 选区浮层抢焦点/位置错 | 保护不可用 | 真实 Lexical 测试；点击 preventDefault；滚动/resize 重算 |
| 页面与弹窗同时保存 | 设置互相覆盖 | 同一草稿模型；页面 focus 刷新；脏值冲突提示 |
| Esc 与 `/` `@` 菜单冲突 | 误关建议/菜单 | 只在有建议且无原生菜单时处理；加测试 |
| i18n 漏 key | 界面混语言 | 字典 key 完整性测试；构建时检查 |
| 窄窗/200% 挤压 | 工具条溢出 | 窄窗截图；换行/收缩策略 |
