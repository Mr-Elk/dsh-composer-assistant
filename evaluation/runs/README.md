# 质量评估运行记录

场景定义在 [`../scenarios/core.json`](../scenarios/core.json)，共 12 条：优化 / 下一句 / 续写各 4 条。
每次改提示词、温度、建议长度或模型后跑一轮，用来比较“改之前”和“改之后”。

## 怎么跑

1. 新开一个会话，按场景的 `setup` 复现上下文（优化直接输入草稿；下一句需要先让助手回复；
   续写直接停在草稿中间）。
2. 触发对应功能：优化点主按钮；下一句等回复结束后看灰字；续写打字后停 600ms。
3. 把建议原文抄进记录表，按三档评分：

| 评分 | 含义 |
| --- | --- |
| 可用 | 可直接发送或采纳，最多改一两个字 |
| 需改 | 方向对，但要改一半以上 |
| 不可用 | 方向错、违反约束、或根本没有建议 |

4. 检查是否命中场景里的 `fail` 反例（命中直接记为不可用，并写明哪一条）。

## 对照规则

一轮只改一个变量（温度 / 建议长度 / 额外指令 / 模型），其余保持默认；每组固定 12 条。
记录文件命名：`YYYY-MM-DD-<主题>.md`，例如 `2026-11-01-baseline.md`、`2026-11-05-temp-0.3.md`。

## 文件格式

```markdown
# 2026-11-01 基线

- 版本：0.2.0
- 设置：标准长度 / 自动触发 / 温度 0.7 / 无额外指令
- 模型：跟随输入框（deepseek-v4.1-flash）

| 场景 | 建议原文 | 评分 | 命中反例 | 备注 |
| --- | --- | --- | --- | --- |
| opt-01 | … | 可用 | 否 | |
```

## 读数

- 可用率 = 可用 / 12；需改与不可用分开记，避免“看起来还行”掩盖方向错误。
- 同一场景连续两轮都不可用，优先改提示词，而不是继续调温度。
