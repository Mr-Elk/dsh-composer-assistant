日期：2026-11-02
状态：P0–P5 已完成；P6 发布等待凭据；错误码化和语言恢复已完成
范围：设置页、关于、文案、开关、真实宿主回归；不改预测/续写/优化主流程。

## 1. 已确认的决定

1. **删除“统计”**：设置页只保留一个“关于”入口。
2. **“恢复默认”不弹确认**：只重置表单，点“保存”才生效。
3. **关闭设置页有未保存改动时提示**：需要先验证 DSH 设置壳是否提供可拦截的关闭钩子；没有公开钩子时不做 DOM 劫持，改用页内提示（见风险）。
4. **不在插件内做自动更新**：DSH 的更新入口是侧边栏“插件”页；本插件“关于”里只保留版本、更新说明和可复制的升级命令。
5. **开关统一为 44 × 24，圆点 20px，左右各 2px。**
6. 所有可见中英文文案按产品说明改写，不使用口语化提示。

### P1 设置页交互（1 天）— 已完成

**关闭钩子 spike 结果（2026-11-02）：DSH 没有公开 before-close。**

- 设置壳 `SettingsPanel` 自己持有 `onClose`；标题关闭按钮、遮罩点击、Escape 都直接调用它。
- section 只拿到同一个 `close: onClose`；没有 before-close 回调。
- `settings.action` 只是标题栏动作槽，`settings.close` 只是关闭按钮的无障碍文案槽。
- 结论：不接公开钩子的前提下，无法拦截壳的关闭。

待选方案：

1. 页内“尚未保存”提示，不拦截（推荐，零耦合）。
2. 标题栏加“保存并关闭”动作；仍无法阻止壳的关闭按钮。
3. DOM 级拦截壳的关闭按钮/遮罩/Escape（不推荐，依赖 DOM 和文案）。
4. 关闭时把未保存草稿存 sessionStorage，重新打开时恢复并提示。


- 保存/恢复默认/未保存状态。
- `恢复默认` 只改表单；保存后生效。
- 冲突提示 + “重新加载”。
- 关闭未保存提示 spike：
  - 先查 DSH settings section 是否有公开 before-close / action 扩展点。
  - 有：接公开钩子。
  - 没有：在页内持续显示“尚未保存”，不监听 shell 关闭；在 `POLISH_PLAN` 记录限制。
- 开关 40×22 的 disabled、深色、200%、触屏。
- i 提示缩短、clamp、翻转。
- 组件测试 + 浅/深/720/200 截图。

验收：

- 无“放弃修改”。
- 重置后保存前不写存储。
- 冲突可重新加载，不覆盖。
- 开关在浅/深/200% 下形状一致。
- 所有可聚焦控件有可见焦点。

## 5. 风险与待验证

1. **关闭未保存提示**：DSH 公开契约只给 section `close()`，shell 的关闭按钮不受插件控制。没有公开 before-close 时，不做 DOM 劫持；需要接受“页内提示但不拦截”或改用“保存并关闭”动作。
2. **插件内更新**：DSH 插件管理器负责安装/更新，并提示重启；插件自身不能安全替换运行中的代码。关于页只做说明和命令，不做假按钮。
3. **统计删除**：如果以后要恢复，先设计持久化计数和口径，不能再用当前运行的内存数字。
4. **真实宿主**：桌面当前是旧 0.3.0；P5 前不能把源码截图当真实宿主证据。
5. **发布**：npm/GitHub 条件不具备时，P6 只能记录阻塞，不能声称已发布。
